# Compatibility invariants

- Keep the existing `/access/requests/<id>` page, duration picker, Authelia passkey ceremony, browser binding, CSRF checks, origin/RP pinning, user verification, and audit behavior. A logged-in browser alone cannot approve a new grant.
- The unprivileged T3/model Unix user cannot read signer keys, provider secrets, lease-signing keys, or change protected policy/artifacts. Native Linux peer credentials authenticate local sockets; user-supplied UID headers never do.
- Grants bind exact capability, selected host, deadline, and browser ceremony. No implicit renewal, task-to-task grant reuse, fallback credentials, SSH agent forwarding, password fallback, or weakened host-key checks.
- Expiry/revoke rejects new operations and closes existing HTTP, WebSocket, terminal, SSH, and provider operations. Remote absolute deadlines and lost-heartbeat shutdown enforce closure even when the hub dies. OS containment limitations must be explicit; ordinary process groups do not contain a hostile administrator or a daemon that deliberately escapes them.
- All ordinary LLM tools execute within the selected remote runtime, including shell working directory, filesystem, terminals, providers, and subprocesses. Grant/lease/deployment chatter stays in deterministic software, out of prompts and model tools.
- Updates bind an administrator-published stable manifest and artifact checksum into a signed, nonce-bound lease. Only complete verified installations replace the active revision. Unavailable targets, protocol mismatch, checksum failure, interruption, or insufficient privilege fail closed and preserve rollback.
- Hub engine build/maintenance stays on t3code. Every configured destination is selectable before connection. Saving a project precedes approval and remote filesystem work; setup progresses in the project. First remote enrollment occurs only after the user selects that destination and approves its timed setup scope; subsequent runtime delivery also occurs under its approved lease. Failed, revoked, or interrupted setup retains the project and never renews access automatically. Upstream self-updaters must not overwrite the patch.
- Preserve native T3 credential/session proof verification through the environment URL prefix. Do not forward hub cookies to remote apps. Pairing secrets stay inside application state, never audit events, URLs, model context, or error messages.
- Regression evidence must cover expiry while connected, denial/revoke during setup, replay, host/manifest tampering, interrupted upgrade, transport loss, URL routing and proof binding, Unix caller isolation, and the unchanged passkey frontend. Never label mocked tests as live passkey or remote tests.
